## [🦄文章&教程](https://weekly.pythoncat.top)

1、[新型 Python 类型检查器对比：Ty、Pyrefly 与 Zuban](https://sinon.github.io/future-python-type-checkers/)

2025 年涌现出三个用 Rust 开发的 Python 类型检查器：Astral 的 ty、Meta 的 pyrefly 和 David Halter 的 zuban。作者通过 Python 类型一致性测试套件深入分析了它们与传统工具 mypy、pyright 的差异，发现 zuban 在测试通过率上领先，但 ty 在工具质量和渐进采用方面更具潜力。

2、[Playwright vs Pydoll 端到端测试性能对比](https://albertomh.com/2025/playwright-vs-pydoll-e2e-benchmark/)

作者在项目中对比测试了 Playwright 和新兴的 pydoll 测试框架，发现 Playwright 在性能上明显优于 pydoll，运行时间更短且稳定性更好。pydoll 虽然基于 Chrome DevTools Protocol 速度更快，但实际测试中代码量多 40%，缺乏内置功能，且仅支持 Chromium 浏览器，目前还不够成熟。

3、[用纯 Python 编写 eBPF 程序](https://xeon.me/gnome/pythonbpf)

PythonBPF 让开发者能够用纯 Python 语法编写 eBPF 程序，通过装饰器和类型注解替代传统的 C 代码字符串嵌入方式。该库将 Python 代码编译成真正的 eBPF 对象文件，支持哈希映射、控制流和内核跟踪等核心功能，为 eBPF 开发提供了除 Rust 和 C 之外的第三种生产级选择。

4、[PEP-804：外部依赖注册表和名称映射机制](https://peps.python.org/pep-0804/)

PEP 804 提出了一个中央注册表机制，用于将 Python 包的外部依赖自动映射到不同包管理中的对应包名。该提案基于 PEP 725 的外部依赖元数据，通过标准化映射规则解决了 Linux 发行版、conda、Homebrew 等生态中包名不一致的问题，能提升跨平台包构建的成功率。

5、[Django 视图编写的最佳实践](https://www.loopwerk.io/articles/2025/django-views/)

作者分析了 Django 视图的三种编写方式，指出通用类视图虽然功能强大但隐藏了过多复杂性，需要理解多达 11 个方法和 5 个类的继承关系。推荐仅使用基础 View 类，通过按 HTTP 方法分离逻辑来组织代码，既避免了函数式视图中的大型 if 块，又保持了代码的简洁性和可读性。

6、[如何用 Python 实现功能开关？](https://rtpg.co/2023/11/15/feature-flags-in-depth/)

功能标志让开发者无需重新部署就能动态控制代码功能。文章介绍了 Python 中的实现方式，从简单的 if 语句判断，到基于 django-waffle 的完整存储架构，再到优雅的 `FeatureFlags` 类设计，详细分享了用户级、团队级、百分比发布等多维度标志策略。

7、[CPython 3.14 远程调试协议解析](https://rtpg.co/2025/06/28/checking-out-sys-remote-exec/)

Python 3.14 即将发布，它新增的 `sys.remote_exec()` 函数可向运行中的 Python 进程注入代码执行，无需重启程序即可进行调试。文章详细演示了如何注入 `traceback.print_stack()` 查看调用栈，或使用 remote_pdb 建立交互式调试会话。

8、[用 6 万张 90 年代 GIF 打造怀旧马赛克动画](https://alexplescan.com/posts/2025/09/15/gifs)

作者从互联网档案馆的 GeoCities 中下载了 6 万多个 GIF 文件，通过 Python 的 imagehash 库实现感知哈希去重，使用 vit-base-nsfw-detector 模型过滤不当内容，最终创建了一个完全在浏览器中渲染的 Canvas 动画，将随机 GIF 拼接成滚动马赛克并添加 CRT 着色器效果。

9、[一个空格删除整个系统？Python 命令注入陷阱](https://pythonkoans.substack.com/p/koan-12-the-blacksmiths-hammer)

文章通过铁匠锤子的比喻分析了 Python 中未引用字符串的危险性，详细解释了 CVE-2024-9287 漏洞成因。当使用 subprocess 的 shell=True 参数时，路径中的空格和分号会被 shell 误解为命令分隔符，导致命令注入攻击。推荐使用 subprocess.run([...]) 避免 shell 解析，或通过 shlex.quote 正确引用字符串。

10、[Playwright 与 pytest 测试技巧分享](https://www.better-simple.com/django/2025/09/17/playwright-pytest-that-brings-me-joy/)

作者分享了在端到端测试中 Playwright 和 pytest 结合的技巧，通过 page.expect_page() 处理新标签页测试，使用 pytest 标记替代夹具来区分不同用户上下文。文章还介绍了 page.pause() 调试工具、axe-playwright-python 包预防可访问性回归，以及 page.expect_response() 确认后台请求的实用方法。

11、[Rye 表格操作与 Python/Pandas 对比](https://ryelang.org/blog/posts/comparing_tables_to_python/)

文章对比了 Rye 语言的表格操作与 Python/Pandas 在数据处理方面的差异，展示了 Rye 如何通过管道操作符和纯函数实现简洁的数据变换。Rye 的表格是一等公民的不可变数据结构，支持链式操作，在处理过滤、连接、聚合等复杂数据任务时比纯 Python 更简洁，与 Pandas 相比语法更直观。

12、[我如何解决 Reddit 的分布式队列问题？](https://www.dbos.dev/blog/durable-queues)

Reddit 前基础设施负责人分享了从传统任务队列到持久化队列的演进历程，通过将检查点状态持久化到 Postgres 等数据库中解决数据丢失问题。持久化队列结合了任务队列与持久化工作流，能从最后完成的步骤恢复失败任务，提供内置可观测性，适合处理业务关键型任务。

13、[RSS 如何击败微软？](https://buttondown.com/blog/rss-vs-ice)

作者揭示了一场鲜为人知的内容聚合标准之争，微软等巨头支持的 ICE 标准虽然功能更强大但过于复杂昂贵，最终败给了简单开放的 RSS。RSS 凭借三要素即可创建订阅源，而 ICE 需要 5.8 万字入门指南，这场技术路线之争印证了互联网"简单开放协议胜过复杂自上而下方案"的铁律。
