1、[Python 单例模式详解：为什么你可能不需要它？](https://www.thepythoncodingstack.com/p/creating-a-singleton-class-in-python)

以游戏排行榜为例，深入讲解单例模式的概念与实现，重点介绍了用 `__new__()` 方法创建对象的技巧。单例模式是其它语言常用的设计模式，但在 Python 中则有更简洁的替代方案——因为模块本身就是天然的单例，使用全局变量和函数往往更优雅。

2、[理解 Python 中的弱引用](https://blog.codingconfessions.com/p/a-strong-reference-to-weak-references)

深入讲解了 Python 内存管理中的弱引用机制，从引用计数的基本原理出发，分析了循环引用导致内存泄漏的问题。通过链表节点的实例演示了强引用和弱引用的区别，说明弱引用如何在不阻止垃圾回收的前提下引用对象，特别适用于缓存和订阅者列表等场景。

3、[使用 wrapt 实现懒加载导入](https://grahamdumpleton.me/posts/2025/10/lazy-imports-using-wrapt/)

介绍了如何利用 wrapt 2.0.0 的新特性 LazyObjectProxy 实现模块懒加载导入，这是对上期分享的 PEP-810 提案的实现。与传统方案不同，它不会修改全局 sys.modules，仅影响使用懒导入的作用域，避免了全局副作用问题。

4、[在 Celery 中使用异步函数与 Django 连接池](https://mrdonbrown.blogspot.com/2025/10/using-async-functions-in-celery-with.html)

深入分析 Django 5.1 连接池与 Celery 异步任务的兼容性问题，详细解释了 Django ORM 异步调用的底层机制，揭示了 `sync_to_async` 如何使用全局线程执行器导致连接泄漏，并提供了基于 `ThreadSensitiveContext` 的完整解决方案，包括自定义 `@async_task` 装饰器和 prefork 模式的处理策略。

5、[杀死 GIL：如何使用 Python 3.14 的自由线程？](https://www.neelsomaniblog.com/p/killing-the-gil-how-to-use-python)

Python 3.14 移除 GIL 实现真正的多线程并行，文章深入分析 GIL 的历史原因、传统并发模型的局限性，并提供详细的编译指南和性能测试。通过 N-Queens 基准测试展示在 M1 Pro 上获得 8 倍性能提升，同时说明 C 扩展重编译和线程安全等注意事项。

6、[实用的 Python REPL 修改技巧](https://treyhunner.com/2025/10/handy-python-repl-modifications/)

通过 PYTHONSTARTUP 文件和 pyrepl-hacks 库定制个性化的 Python 3.13+ REPL 体验，文章介绍如何添加自定义键盘快捷键、语法高亮主题，以及创建便捷的代码编辑功能，让 REPL 更像现代编辑器。

7、[聊聊 Python 中的 UUID 安全](https://www.cnblogs.com/LAMENTXU/articles/18921150)

深入分析 Python UUID 各版本的安全隐患和攻击方式，详解了 UUIDv1-v8 的生成逻辑，揭示 PRNG 与 CSPRNG 的安全差异，介绍 Sandwich Attack 等实战攻击技术，并提供完整的攻击流程和防护建议。

8、[在 GitHub Actions 中使用自由线程 Python](https://hugovk.dev/blog/2025/free-threaded-python-on-github-actions/)

GitHub Actions 现已支持实验性自由线程 CPython 测试，文章介绍了三种配置方法：使用 t 后缀、setup-uv 和 freethreaded 变量，提供完整的 CI 配置示例和环境变量设置。

9、[为什么 2025 年仍需第三方应用来开发 Django REST API？](https://emma.has-a.blog/articles/why-do-we-need-an-external-app-for-rest.html)

挑战传统观念，展示如何仅用 Django 内置功能开发完整的 REST API。作者通过 JsonViewMixin 和 ModelForm 巧妙实现序列化，配合通用类视图处理 CRUD 操作，证明在简单场景下无需 DRF 也能优雅地实现 API 功能。

10、[将 Python ASGI 引入 Node.js 应用](https://blog.platformatic.dev/bring-python-asgi-to-your-nodejs-applications)

介绍了一种创新的技术方案，让 Python ASGI 应用能够直接在 Node.js 进程内运行。通过 Rust 构建的桥接层，实现了零网络开销的进程内通信，无需启动独立的 Python 进程或网络连接。这种架构特别适合需要低延迟的 AI/ML 应用场景，同时支持 FastAPI、Django 等主流 Python 框架。

11、[用 EchoAPI 的 AI 功能增强 API 测试](https://geekpython.in/echoapi-ai)

AI 技术如何革新 API 测试流程？文章介绍了 EchoAPI，它支持用自然语言描述测试需求自动生成可执行脚本和断言，能够智能分析 API 响应结构，自动创建覆盖边界情况的测试用例，并生成动态变量和虚拟数据。

![](https://img.pythoncat.top/2025-10-17-EchoAPI.png)

12、[Python 时间差计算的隐藏陷阱](https://www.mostlypython.com/time-deltas-are-not-intuitive/)

作者在开发时间追踪应用时发现了 timedelta 对象的一个常见误区：跨天计算时长时只使用 `seconds` 属性会得到错误结果。深入解释了 Python 如何将时间差标准化为天、秒、微秒三个属性存储，揭示了为什么要用 `total_seconds()` 方法或手动计算 `(days * 24) + (seconds / 3600)` 才能获得准确的小时数。
