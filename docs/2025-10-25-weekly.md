## [🦄文章&教程](https://weekly.pythoncat.top)

1、[跳出 AI 热潮：Guido van Rossum 谈 Python 哲学、简洁性与编程未来](https://www.odbms.org/blog/2025/10/beyond-the-ai-hype-guido-van-rossum-on-pythons-philosophy-simplicity-and-the-future-of-programming/)

Python 之父 Guido van Rossum 访谈：强调代码仍需人类审查，Python 的"人文主义"哲学让 LLM 也能轻松理解；对 GIL 移除持理性观点，认为大企业需求正让 Python 变得复杂；建议万行以上代码才用类型提示，保持对初学者友好。

2、[Python Web 服务的无 GIL 未来](https://blog.baro.dev/p/the-future-of-python-web-services-looks-gil-free)

基于 Python 3.14 无 GIL 版本做 FastAPI 和 Flask 基准测试，作者发现无 GIL 版本性能损失从 35% 降至 5-10%，内存使用显著减少。在 I/O 密集型场景下，无 GIL 版本略胜标准版本，这为 Python Web 服务带来了真正的多线程并发能力，有望减少对多进程架构的依赖。

3、[告别 GIL：探索 Python 3.14 无 GIL 模式](https://blog.adarshd.dev/posts/exploring-free-threaded-python-314/)

作者在 PyCon JP 2025 分享的深度基准测试报告，通过对比 Python 3.14 标准版和无 GIL 版本，发现单线程代码性能损失约 15%，但多线程 CPU 密集型任务获得显著提升，还介绍了无 GIL 模式的设置方法、性能表现和实际应用场景。

4、[懒加载导入：让 Python 启动速度提升 3 倍](https://hugovk.dev/blog/2025/lazy-imports/)

针对 PEP 810 提出的显式懒加载导入功能，作者通过测试 pypistats CLI 工具发现，懒加载导入将启动时间从 104ms 缩短到 36ms，性能提升近 3 倍。这对命令行工具、测试套件和大型依赖图应用特别有益，能显著减少启动时间和内存使用。

5、[现在就能用的 Python 懒加载导入技巧](https://pythontest.com/python-lazy-imports-now/)

介绍在现有 Python 版本中实现懒加载导入的实用技巧，通过将导入语句移入函数内部来延迟模块加载。文章演示了多种实现方法，包括使用 importlib.import_module() 和 python -X importtime 诊断慢导入。

6、[Diskcache：不只是缓存](https://www.bitecode.dev/p/diskcache-more-than-caching)

深入介绍基于 SQLite 的 Python 本地缓存库 diskcache，它不仅提供微秒级的键值存储，还支持事务、标签、锁定和队列等高级功能。通过分片机制实现多进程并发写入，内置防雷群效应和函数装饰器，几乎可以替代轻量级 Redis 使用场景。

7、[用 Postgres 做任务队列的经验](https://leontrolski.github.io/postgres-as-queue.html)

作者分享使用 PostgreSQL 作为任务队列的实践经验，通过 FOR UPDATE SKIP LOCKED 实现原子锁定，避免了额外的基础设施配置和复杂的重试机制。相比传统消息队列，这种方案减少了系统复杂度，提供了更好的可观测性，还能轻松添加重试、延迟执行等功能。

8、[为什么 Python 开发中性能很重要？](https://blog.jetbrains.com/pycharm/2025/10/why-performance-matters-in-python-development/)

文章从 Python 解释器特性和 GIL 限制入手，详细分析了常见性能陷阱，包括不必要的循环、字符串拼接、数据结构误用等，强调性能优化不仅影响用户体验和云成本，还直接关系到系统可扩展性和开发效率。

9、[异步 Django：寻找问题的解决方案？](https://www.loopwerk.io/articles/2025/async-django-why/)

作者质疑 Django 异步功能的实用价值，虽然 Django 团队花费六年时间开发异步特性，但 2024 年调查显示仅 14% 开发者使用异步视图。文章指出异步 Django 增加了框架复杂度，产生双重 API，而传统的后台任务处理方案（如 Celery）仍是解决性能瓶颈的最佳选择。

10、[Django bulk_update 内存问题](https://blog.pecar.me/django-bulk-update-memory-issue)

作者在处理数十万条数据库记录更新时发现 Django bulk_update 的内存陷阱，虽然设置了 batch_size 参数，但 Django 仍会预先准备所有批次的 UPDATE 语句，导致内存暴增至 4.8GB 并触发 SIGTERM。解决方案是手动实现批处理循环，将内存使用降至仅 62MB。

11、[Python 属性测试的实证评估](https://cseweb.ucsd.edu/~mcoblenz/assets/pdf/OOPSLA_2025_PBT.pdf)

OOPSLA 2025 论文首次系统评估 Python 属性测试的实际效果，研究发现属性测试在发现 bug 方面表现出色，特别是针对边界条件和异常输入。通过对比传统单元测试，属性测试能自动生成大量测试用例，显著提高代码覆盖率和 bug 检测能力。

12、[从 Python 到 Kotlin：值得一试的转换](https://blog.jetbrains.com/kotlin/2025/10/from-python-to-kotlin-a-transition-worth-making/)

文章分析了从 Python 迁移到 Kotlin 的优势。虽然两种语言语法相似，但 Kotlin 提供静态类型、不可变性和更强的并发模型，基准测试显示 Python 比 Java 慢 10-100 倍，而 Kotlin 继承了 JVM 的高性能，它的类型安全和现代语言特性能显著提升开发效率。
