## [🦄Articles & Tutorials](https://weekly.pythoncat.top)

1、[Reflections on 2 years of CPython's JIT Compiler: The good, the bad, the ugly](https://fidget-spinner.github.io/posts/jit-reflections.html)

Ken Jin, a core developer of CPython's JIT compiler, reflects on two years of development, candidly analyzing the project's successes and challenges. He highlights how the JIT successfully adopted a community-driven development model, attracting numerous contributors. However, performance remains disappointing—often slower than the interpreter under modern compilers. Version 3.15 might finally deliver the real performance gains we've been waiting for.

2、[Types are Transforming Python](https://spin.atomicobject.com/types-are-transforming-python/)

This piece traces Python's type system evolution, explaining the major shifts since the typing module landed in Python 3.5. It spotlights NamedTuple and dataclass syntax, showing how class-based type creation became more intuitive and elegant. The article also covers advanced features like generics, NewType, and TypedDict. Combined with tools like pyright and Pylance, the type system isn't just improving code quality—it's fundamentally transforming how we write Python.

3、[Solving Wordle with uv's dependency resolver](https://mildbyte.xyz/blog/solving-wordle-with-uv-dependency-resolver)

This clever hack transforms Wordle into a Python package dependency problem, using thousands of virtual package versions to represent letter position constraints and leveraging uv's blazing-fast dependency resolution to automatically solve puzzles. Who knew dependency managers could have such unexpected uses? (Previously, we shared [solving Sudoku with Python package resolvers](https://simonwillison.net/2024/Oct/21/sudoku-in-python-packaging/))

4、[Developing a Real-time Dashboard with FastAPI, MongoDB, and WebSockets](https://testdriven.io/blog/fastapi-mongo-websockets)

How do you build a real-time order management dashboard? This tutorial uses MongoDB Change Streams to monitor data changes, combines FastAPI WebSockets for real-time frontend-backend communication, and leverages the Motor async driver for performance gains. It's a solid showcase of modern web app real-time data processing best practices.

5、[Escaping Contravariance Hell](https://labs.quansight.org/blog/escaping-contravariance-hell)

Don't panic when your type checker screams about "violating the Liskov substitution principle." This article brilliantly explains contravariance using vegetable peelers: a carrot peeler can only peel carrots—you can't use it as a generic vegetable peeler. The solution? Generic protocols and TypeVar to let the type system know exactly which peeler works with which veggie, avoiding the temptation to just slap Any everywhere and call it a day.

6、[LangFlow Tutorial: Building Production-Ready AI Applications With Visual Workflows](https://www.firecrawl.dev/blog/langflow-tutorial-visual-ai-workflows)

LangFlow makes AI app development as easy as playing with Legos! Drag and drop pre-built components to create complex workflows, building multi-agent systems and RAG applications without writing a single line of code. This tutorial walks through building a Firecrawl search component, covering everything from environment setup to component development to workflow integration.

7、[Scaling recommendations service at OLX](https://tech.olx.com/scaling-recommendations-service-at-olx-db4548813e3a)

The OLX team shares how they scaled their FastAPI recommendation service to handle tens of thousands of requests per second with p99 latency under 10ms. Through async I/O optimization, batched queries to reduce fan-out, removing Pydantic validation overhead, and tuning garbage collection parameters, they achieved a 40% reduction in latency and 50% boost in throughput.

8、[Getting extensions to work with free-threaded Python](https://lwn.net/Articles/1025893/)

Python 3.13's free-threaded mode ditches the GIL, but how do you get existing extensions to play nice? The Quansight Labs and Meta teams share their ecosystem migration experience—the key is handling global state races. Using mutexes to protect shared variables, atomic operations to avoid deadlocks, redesigning mutable data structures, and tools like ThreadSanitizer to catch data races, Python is finally ready to embrace the multi-threaded era.

9、[Augmented Coding: Beyond the Vibes](https://tidyfirst.substack.com/p/augmented-coding-beyond-the-vibes)

Through hands-on experience building a B+ Tree library, the author contrasts "Augmented Coding" with "Vibe Coding." The former emphasizes human-AI collaboration where developers stay in the driver's seat, using TDD and clean code principles to guide AI toward generating high-quality code that's more reliable and maintainable.

10、[Context Engineering for Agents](https://rlancemartin.github.io/2025/06/23/context_engineering/)

Context engineering has suddenly exploded in popularity. This article breaks it down into four key strategies: write (save outside the context window), select (pull in relevant info), compress (keep essential tokens), and isolate (split processing). Through practical examples like sticky notes, memory systems, and multi-agent architectures, it shows how to elegantly solve context management challenges in long conversations.

![Context engineering](https://img.pythoncat.top/2025-07-11-context_engineering.png)

11、[PyTorch is dead. Long live JAX.](https://neel04.github.io/my-website/blog/pytorch_rant/#coalescing-ecosystem)

The author delivers a scathing critique of PyTorch's design philosophy, pointing out how its pursuit of flexibility creates performance bottlenecks at scale. PyTorch tries to have its cake and eat it too—balancing dynamic features with compiler optimization—leading to serious feature fragmentation. JAX, on the other hand, was built around the XLA compiler from day one, using functional programming and pure function constraints to achieve more elegant distributed training and automatic parallelization.

12、[operators, not users and programmers](https://jyn.dev/computer-of-the-future)

From the "Computers of the Next 200 Years" series, the author drops a bombshell: the distinction between "users" and "programmers" is harmful and kills people's agency. Using spreadsheets as a success story, they show how malleable software can make programming as natural as writing a resume. The article envisions future computing systems with hot reloading, automatic persistence, distributed version control, instant testing, and continuous deployment—turning everyone into computer "operators."
