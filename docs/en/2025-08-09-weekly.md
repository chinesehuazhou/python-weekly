## [🦄Articles & Tutorials](https://weekly.pythoncat.top)

1、[How JIT builds of CPython actually work](https://savannah.dev/posts/how-your-code-runs-in-a-jit-build/)

A deep dive into CPython's JIT compilation mechanism, covering the complete pipeline from token parsing to bytecode to machine code. It reveals how the experimental JIT in 3.14 transforms hot code into native instructions using micro-op and copy-and-patch techniques, helping you understand Python's performance optimization roadmap.

2、[Why I'm interested in Litestar](https://www.b-list.org/weblog/2025/aug/06/litestar/)

Litestar is an emerging async Python web framework. The author discovered that its independent route decorators solve circular import issues, with built-in support for multiple validation schemes like Pydantic, dataclasses, and msgspec. It deeply integrates with SQLAlchemy and Advanced Alchemy to auto-generate data repositories, providing elegant scalable architecture for large projects.

3、[You might not need a Python class](https://adamgrant.micro.blog/2025/07/24/123050.html)

The author points out that Python's built-in types and standard library can elegantly handle most scenarios: use namedtuple or dataclass instead of simple data containers, functions instead of stateless utility classes, modules for natural constant grouping, and dict/list for state management. Leverage the standard library to avoid over-engineering and keep code clean and Pythonic.

4、[Rust, Python, and TypeScript: the new trifecta](https://smallcultfollowing.com/babysteps/blog/2025/07/31/rs-py-ts-trifecta/)

The author predicts that the AI programming era will reshape language selection: Rust handles system-level performance, Python provides math and ML ecosystems, TypeScript dominates web and tooling. These three complement each other in type safety and dependency management, forming a future-oriented full-stack tech stack.

5、[Python performance myths and fairy tales](https://lwn.net/SubscriberLink/1031707/73cb0cf917307a93/)

A PyPy core developer's EuroPython talk debunks performance myths: "Python is fast enough" only applies to certain scenarios, rewriting hot code will eventually hit walls, static typing doesn't help runtime optimization. The real bottlenecks lie in memory management and language semantics. The author is developing the SPy project to explore ultra-high-performance Python paths.

6、[Ways to have an atomic counter in Django](https://blog.ovalerio.net/archives/2924)

The article introduces three Django counting solutions to avoid race conditions: database locking with `select_for_update`, atomic operations with `F()` expressions, and cache layer with `cache.incr`. Choose flexibly based on precision requirements.

7、[Don't call dunder methods](https://www.pythonmorsels.com/avoid-dunder-methods/)

The author argues you should define dunder methods for Python's interpreter to call, not call them directly. Use high-level interfaces like str(), len(), in instead of obj.\_\_str\_\_(), obj.\_\_len\_\_() to avoid low-level details and ensure consistent behavior.

8、[Render your Jupyter notebooks in OpenGist](https://blog.fabiomanganiello.com/article/render-your-jupyter-notebooks-in-opengist)

OpenGist's frontend natively supports .ipynb file rendering, displaying notebooks like GitHub without backend changes. It supports code highlighting, Markdown, and LaTeX, letting you elegantly share Jupyter workflows through self-hosted private gist services.

9、[Updating Python](https://www.mostlypython.com/updating-python/)

The author shares their experience migrating from pyenv to uv: first uninstall old versions with pyenv, remove redundant installations with brew, then unify local Python management with uv for simpler version switching and a cleaner system.

10、[Conda Ecosystem Explained](https://conda.org/blog/2024-08-14-conda-ecosystem-explained)

The article systematically outlines conda's three pillars: cross-language CLI tools, channelized package repositories (conda-forge, bioconda, etc.), and build systems. It highlights how new tools like Mamba and Pixi maintain compatibility with core formats, clarifying the vast conda ecosystem.

11、[What's the deal with setuptools & setup.py](https://www.bitecode.dev/p/whats-the-deal-with-setuptools-setuppy)

The article traces setuptools' evolution: from early distutils' setup\.py to setuptools' declarative configuration, then to pyproject\.toml's modern standard. It notes that while setup\.py remains usable, it's no longer necessary—new projects should embrace pyproject\.toml's clean unification.

12、[Everything I know about good system design](https://www.seangoedecke.com/good-system-design)

The author distills system design essentials: good design should be simple and straightforward, state management is the biggest challenge, database design is most critical. Minimize stateful components and use simple, evolvable architectures instead of overly complex distributed solutions.
