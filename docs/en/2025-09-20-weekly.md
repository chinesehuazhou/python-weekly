## [🦄Articles & Tutorials](https://weekly.pythoncat.top)

1、[How Well Do New Python Type Checkers Conform? A Deep Dive into Ty, Pyrefly, and Zuban](https://sinon.github.io/future-python-type-checkers/)

Three new Rust-powered Python type checkers emerged in 2025: Astral's ty, Meta's pyrefly, and David Halter's zuban. The author conducted an in-depth analysis using Python's type conformance test suite to compare these newcomers against established tools like mypy and pyright. While zuban leads in test pass rates, ty shows greater promise for tool quality and gradual adoption strategies.

2、[Playwright vs Pydoll](https://albertomh.com/2025/playwright-vs-pydoll-e2e-benchmark/)

The author benchmarked Playwright against the emerging pydoll testing framework in their project, finding Playwright significantly outperformed pydoll with shorter execution times and better stability. Despite pydoll's faster Chrome DevTools Protocol foundation, it required 40% more code in practice, lacked built-in features, and only supported Chromium browsers—making it not quite ready for prime time.

3、[PythonBPF - Writing eBPF Programs in Pure Python](https://xeon.me/gnome/pythonbpf)

PythonBPF enables developers to write eBPF programs using pure Python syntax, replacing traditional C code string embedding with decorators and type annotations. The library compiles Python code into genuine eBPF object files, supporting core features like hash maps, control flow, and kernel tracing—offering a third production-ready option for eBPF development alongside Rust and C.

4、[PEP 804 – An external dependency registry and name mapping mechanism](https://peps.python.org/pep-0804/)

PEP 804 proposes a central registry mechanism for automatically mapping Python packages' external dependencies to corresponding package names across different package managers. Building on PEP 725's external dependency metadata, this proposal uses standardized mapping rules to solve package name inconsistencies across Linux distributions, conda, Homebrew, and other ecosystems, boosting cross-platform build success rates.

5、[How I write Django views](https://www.loopwerk.io/articles/2025/django-views/)

The author analyzes three approaches to writing Django views, pointing out that while generic class-based views are powerful, they hide too much complexity—requiring understanding of up to 11 methods and 5 class inheritance relationships. They recommend using only the base View class, organizing code by separating logic according to HTTP methods, avoiding large if-blocks in function-based views while maintaining code simplicity and readability.

6、[Feature Flags In Depth](https://rtpg.co/2023/11/15/feature-flags-in-depth/)

Feature flags let developers dynamically control code functionality without redeployment. This article covers Python implementation approaches, from simple if-statement checks to complete storage architectures using django-waffle, and elegant `FeatureFlags` class designs. It details multi-dimensional flag strategies including user-level, team-level, and percentage rollout configurations.

7、[Checking Out CPython 3.14's remote debugging protocol](https://rtpg.co/2025/06/28/checking-out-sys-remote-exec/)

Python 3.14 is coming with a new `sys.remote_exec()` function that can inject code execution into running Python processes without requiring program restarts for debugging. The article demonstrates how to inject `traceback.print_stack()` to view call stacks or use remote_pdb to establish interactive debugging sessions.

8、[Just for fun: animating a mosaic of 90s GIFs](https://alexplescan.com/posts/2025/09/15/gifs)

The author downloaded over 60,000 GIF files from the Internet Archive's GeoCities collection, using Python's imagehash library for perceptual hash deduplication and the vit-base-nsfw-detector model to filter inappropriate content. The result is a fully browser-rendered Canvas animation that stitches random GIFs into a scrolling mosaic with CRT shader effects.

9、[Koan 12: The Blacksmith's Hammer](https://pythonkoans.substack.com/p/koan-12-the-blacksmiths-hammer)

Using the metaphor of a blacksmith's hammer, this article analyzes the dangers of unquoted strings in Python, explaining the root cause of CVE-2024-9287. When using subprocess with shell=True, spaces and semicolons in paths get misinterpreted by the shell as command separators, leading to command injection attacks. The recommended solutions are using subprocess.run([...]) to avoid shell parsing or properly quoting strings with shlex.quote.

10、[Playwright & pytest techniques that bring me joy](https://www.better-simple.com/django/2025/09/17/playwright-pytest-that-brings-me-joy/)

The author shares techniques for combining Playwright and pytest in end-to-end testing, using page.expect_page() to handle new tab testing and pytest markers instead of fixtures to distinguish different user contexts. The article also covers page.pause() debugging tools, the axe-playwright-python package for preventing accessibility regressions, and page.expect_response() for confirming background requests.

11、[Rye Tables vs Python/Pandas: A Different Way to Wrangle Data](https://ryelang.org/blog/posts/comparing_tables_to_python/)

This article compares Rye language's table operations with Python/Pandas for data processing, showcasing how Rye achieves clean data transformations through pipeline operators and pure functions. Rye's tables are first-class immutable data structures supporting chained operations, offering more concise syntax than pure Python for complex data tasks like filtering, joining, and aggregation, with more intuitive syntax compared to Pandas.

12、[How I solved a distributed queue problem after 15 years](https://www.dbos.dev/blog/durable-queues)

Reddit's former infrastructure lead shares the evolution from traditional task queues to durable queues, solving data loss issues by persisting checkpoint state to databases like Postgres. Durable queues combine task queues with durable workflows, enabling recovery from the last completed step for failed tasks, providing built-in observability perfect for business-critical tasks.

13、[The story of how RSS beat Microsoft](https://buttondown.com/blog/rss-vs-ice)

The author reveals a little-known battle of content syndication standards, where Microsoft and other giants' ICE standard—despite being more powerful—was too complex and expensive, ultimately losing to simple, open RSS. RSS could create feeds with just three elements, while ICE required a 58,000-word getting-started guide. This technical battle proved the internet's iron law: "simple, open protocols beat complex, top-down solutions."
