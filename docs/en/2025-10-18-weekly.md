# Python Trending Weekly #123: You Probably Don't Need the Singleton Pattern



## [🦄Articles & Tutorials](https://xiaobot.net/p/python_weekly)

1、[Creating a Singleton Class in Python And Why You (Probably) Don't Need It](https://www.thepythoncodingstack.com/p/creating-a-singleton-class-in-python)

Using a game leaderboard as an example, this article dives deep into the singleton pattern concept and implementation, with a focus on the clever technique of using the `__new__()` method for object creation. While the singleton pattern is commonly used in other languages, Python offers more elegant alternatives—since modules themselves are natural singletons, using global variables and functions is often more graceful.

2、[Understanding Weak References in Python](https://blog.codingconfessions.com/p/a-strong-reference-to-weak-references)

A comprehensive exploration of Python's weak reference mechanism in memory management, starting from the fundamentals of reference counting and analyzing how circular references lead to memory leaks. Through linked list node examples, it demonstrates the difference between strong and weak references, explaining how weak references can reference objects without preventing garbage collection—particularly useful for caching and subscriber list scenarios.

3、[Lazy imports using wrapt](https://grahamdumpleton.me/posts/2025/10/lazy-imports-using-wrapt/)

This article introduces how to leverage wrapt 2.0.0's new LazyObjectProxy feature for lazy module imports, implementing the PEP-810 proposal shared in a previous issue. Unlike traditional approaches, it doesn't modify the global sys.modules, only affecting the scope where lazy imports are used, avoiding global side effects.

4、[Using Async Functions in Celery with Django Connection Pooling](https://mrdonbrown.blogspot.com/2025/10/using-async-functions-in-celery-with.html)

An in-depth analysis of compatibility issues between Django 5.1 connection pooling and Celery async tasks, providing detailed explanations of Django ORM async call mechanisms. It reveals how `sync_to_async` uses global thread executors leading to connection leaks, and offers a complete solution based on `ThreadSensitiveContext`, including custom `@async_task` decorators and prefork mode handling strategies.

5、[Killing the GIL: How To Use Python 3.14's Free-Threading Upgrade](https://www.neelsomaniblog.com/p/killing-the-gil-how-to-use-python)

Python 3.14 removes the GIL to achieve true multithreaded parallelism. This article analyzes the historical reasons for the GIL, limitations of traditional concurrency models, and provides detailed compilation guides and performance testing. Through N-Queens benchmarks, it demonstrates an 8x performance boost on M1 Pro, while explaining considerations for C extension recompilation and thread safety.

6、[Handy Python REPL Modifications](https://treyhunner.com/2025/10/handy-python-repl-modifications/)

Customize your Python 3.13+ REPL experience through PYTHONSTARTUP files and the pyrepl-hacks library. The article shows how to add custom keyboard shortcuts, syntax highlighting themes, and convenient code editing features, making the REPL feel more like a modern editor.

7、[Let's Talk About UUID Security in Python](https://www.cnblogs.com/LAMENTXU/articles/18921150)

A deep dive into security vulnerabilities and attack methods across different Python UUID versions, detailing the generation logic of UUIDv1-v8, revealing security differences between PRNG and CSPRNG, introducing practical attack techniques like Sandwich Attack, and providing comprehensive attack workflows and protection recommendations.

8、[Free-threaded Python on GitHub Actions](https://hugovk.dev/blog/2025/free-threaded-python-on-github-actions/)

GitHub Actions now supports experimental free-threaded CPython testing. The article covers three configuration methods: using the 't' suffix, setup-uv, and freethreaded variables, providing complete CI configuration examples and environment variable setup.

9、[Why, in 2025, do we still need a 3rd party app to write a REST API with Django?](https://emma.has-a.blog/articles/why-do-we-need-an-external-app-for-rest.html)

Challenging conventional wisdom, this article demonstrates how to build a complete REST API using only Django's built-in features. The author cleverly implements serialization through JsonViewMixin and ModelForm, combined with generic class views for CRUD operations, proving that DRF isn't always necessary for elegant API functionality in simple scenarios.

10、[Bring Python ASGI to Your Node.js Applications](https://blog.platformatic.dev/bring-python-asgi-to-your-nodejs-applications)

Introducing an innovative technical solution that allows Python ASGI applications to run directly within Node.js processes. Through a Rust-built bridge layer, it achieves zero network overhead in-process communication without needing separate Python processes or network connections. This architecture is particularly suited for low-latency AI/ML application scenarios while supporting mainstream Python frameworks like FastAPI and Django.

11、[Power-up API Testing with EchoAPI's AI](https://geekpython.in/echoapi-ai)

How is AI technology revolutionizing API testing workflows? This article introduces EchoAPI, which supports natural language descriptions of testing requirements to automatically generate executable scripts and assertions, intelligently analyzes API response structures, automatically creates test cases covering edge cases, and generates dynamic variables and mock data.

![](https://img.pythoncat.top/2025-10-17-EchoAPI.png)

12、[Time deltas are not intuitive](https://www.mostlypython.com/time-deltas-are-not-intuitive/)

While developing a time tracking application, the author discovered a common pitfall with timedelta objects: using only the `seconds` attribute when calculating durations across days yields incorrect results. The article explains in detail how Python normalizes time differences into three attributes—days, seconds, and microseconds—revealing why you need to use the `total_seconds()` method or manually calculate `(days * 24) + (seconds / 3600)` to get accurate hour counts.
